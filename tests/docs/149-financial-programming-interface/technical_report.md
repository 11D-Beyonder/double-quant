# 149 面向金融人员的编程开发接口技术报告

## 技术目标

本功能面向“面向金融人员的编程开发接口”的验收要求。金融人员通常关注数据来源、金融指标、算法参数和结果解释，而不是底层量子线路语法或运行环境细节。因此该功能被设计为金融编程开发页面的第三步，在前两步完成金融软件对接和数据格式治理后，为金融人员提供一个可查看源码、可选择模板、可设置参数、可运行并可查看金融结果的工作区。

## 为什么这样实现

如果直接把金融人员带到通用代码编辑器或量子线路编辑器，用户需要理解较多底层概念，无法体现“面向金融人员”的接口特点。当前实现采用“生成源码 + 参数控件 + 运行结果 + 金融解释”的方式，是为了在保留源码透明度的同时降低操作门槛。金融人员可以看到平台如何把标准化行情数据组织成可运行逻辑，也可以通过选择算法模板和参数控件完成操作，而不必从零编写量子程序。

该功能被放在三步流程的第三步，是因为金融编程不应孤立存在。第一步解决金融软件来源，第二步解决数据格式与质量，第三步才进行编程执行。这样拆分后，149 不再包含 146 和 147 的验收内容，而是专注验证“金融人员如何使用标准数据进行编程和查看结果”。

## 功能组成

界面由源码编辑区、算法模板入口、参数设置区、运行按钮、量子线路展示区、金融结果展示区和概率分布图组成。源码编辑区用于展示由前置数据生成的金融编程源码；算法模板用于切换金融问题类型；参数控件用于设置问题类型、shots 等运行参数；运行结果区用于展示量子线路统计、金融指标、估值对象、运行时间和测量分布。

这些组成部分对应金融人员的典型工作过程：先确认输入数据和生成逻辑，再选择算法和参数，然后运行，最后根据金融结果和概率分布判断计算结果是否符合预期。

## 源码生成与可解释性

面向金融人员的源码区并不是为了替代专业开发环境，而是为了让生成逻辑透明。前置步骤完成软件对接和格式标准化后，源码区域展示标准化行情数据、收益率计算、金融问题构造和算法调用等内容。这样用户可以理解平台如何把外部数据转成可运行的金融程序，也可以在需要时进行局部调整。

采用源码展示而不是只显示“运行”按钮，是因为验收指标强调“编程开发接口”。接口需要体现可编程性、可检查性和可修改性。源码区提供了这种透明度，参数区提供了低门槛操作能力，两者组合更符合金融人员从数据到结果的使用方式。

## 运行结果设计

运行结果采用多种视图组织：量子线路图用于展示算法执行结构，指标卡片用于展示金融结果摘要，概率分布图用于展示测量结果分布。选择这些视图的原因是金融人员需要同时理解“算法是否运行”“运行规模如何”“结果是什么”“结果分布是否集中”。单一文本输出无法满足这种解释需求。

概率分布图和金融结果区共同服务于结果解释。金融结果给出业务含义，概率分布给出量子测量层面的分布情况。两者同时展示，可以让金融人员在不深入底层实现的情况下判断结果是否稳定、是否具有明显倾向。

## 交互与状态流转

用户完成前两步后进入第三步，页面显示金融编程源码。用户选择算法模板和运行参数后点击“运行”，页面更新量子线路、运行统计、金融指标和概率分布。这个过程形成“标准数据进入源码、参数控制运行、结果回到可视化面板”的闭环。

该闭环体现了面向金融人员的设计逻辑：用户不需要离开当前页面，也不需要在多个系统之间切换；同一界面承载源码、运行和结果分析。这样既保留了编程接口的可见性，又降低了金融人员进行量子金融实验的门槛。

## 验收关注点

本功能的验收重点包括：是否存在金融编程源码区；是否能够从前置数据生成源码；是否提供算法模板和参数设置；是否有运行按钮；运行后是否展示量子线路、金融结果和概率分布；界面是否以金融人员容易理解的方式组织结果。截图中展示了源码生成、编辑区同步和运行后的可视化结果，能够支撑 UI 操作型验收。

## 技术边界

本功能验证的是面向金融人员的编程开发界面能力，不评价具体金融算法的收益水平，也不展开底层量子后端性能或部署流程。算法正确性、性能基准和真实业务收益需要由独立算法测试或性能测试覆盖。该报告只说明界面如何承载金融人员从数据到源码、从参数到结果的开发流程。

## 技术结论

该实现将金融软件对接和数据格式治理后的标准数据引入金融编程工作区，通过源码区、参数控件、运行入口、量子线路、金融结果和概率分布图，形成面向金融人员的可视化编程开发接口。其设计重点是用透明源码和可视化结果降低使用门槛，同时保留编程接口应有的可检查性和可解释性。

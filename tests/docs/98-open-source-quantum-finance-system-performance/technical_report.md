# 98 开源原型量子金融软件系统构建及开发效率与性能提升测试（Perf-36） 技术报告

## 技术目标

建立一套面向开源原型量子金融软件系统的可复核性能验收流程，验证系统构建、开发效率提升和性能提升三类要求。

## 实现位置

- 测试脚本：`tests/double_quant/programming/98-open_source_quantum_finance_system_performance.py`
- 文档目录：`tests/docs/98-open-source-quantum-finance-system-performance/`
- 开源接口入口：`src/double_quant/__init__.py`、`src/double_quant/application/`、`src/double_quant/programming/`

## 实现概述

脚本显式导入 `double_quant`，并通过开源软件接口构建或求解十类金融算法。每个用例保存两段代码：一段为开源软件接口调用，一段为直接量子线路或直接数值流程。脚本统计有效代码行数，并采集运行耗时或线路资源成本，最终生成两张中文柱状图。

## 关键技术点

- 系统构建：十类算法均有独立用例，输出构建证据和资源摘要。
- 开发效率：以有效代码行数衡量，注释和空行不计入。
- 性能提升：估值类和求解类采用毫秒耗时；线路构建类优先采用量子门数量，其次采用线路深度或量子位数量。
- 图表表达：开发效率柱状图展示直接量子线路与开源软件接口的代码行数，性能提升柱状图展示归一化成本。
- 命名约束：报告和图表只展示十类中文算法名称，编程语言体系只展示“决策性问题”和“估值性问题”。

## 验收脚本设计

每个 `AcceptanceCase` 记录算法名称、编程语言体系、开源软件接口代码、直接量子线路代码、输出结果、性能指标和构建证据。脚本断言十类算法全覆盖、两类编程语言体系全覆盖、开源软件接口代码行数更少且性能成本更低。

## 技术结论

当前开源原型量子金融软件系统可以构建十类金融算法，并通过统一接口减少直接量子线路开发成本。在固定验收样例上，开发效率与性能成本均形成可量化提升。

## 技术原理补充：开发效率与性能提升的统一评价模型

Perf-36 同时评价开源原型系统构建、开发效率和性能成本。对第 $j$ 个算法，开发效率提升定义为

$$
S^{dev}_j=\frac{L^{direct}_j}{L^{open}_j},
$$

其中 $L^{direct}_j$ 是直接线路或直接数值流程的有效代码行数，$L^{open}_j$ 是使用开源软件接口的有效代码行数。性能提升定义为

$$
S^{perf}_j=\frac{C^{direct}_j}{C^{open}_j}.
$$

对于估值或求解类算法，$C$ 采用运行耗时毫秒；对于线路构建类算法，$C$ 优先采用量子门数量，必要时用线路深度或量子位数补充。这样可以避免把“线路尚未真实硬件运行”的场景误写成硬件加速，同时仍能比较开源接口是否降低了构建成本。

## 开源原型系统构建的技术含义

“系统构建”不是只验证 `import double_quant`，而是验证十类算法均能通过公共入口完成至少一种可观测输出：

$$
\forall k\in\{1,\ldots,10\},\quad \exists\ \mathcal{O}_k: x_k\mapsto y_k.
$$

其中 $y_k$ 可以是组合权重、风险值、期权价格、量子线路、最优比特串或资源摘要。公共入口把源码组织为数据层、算法层、应用层和编程框架层，第三方使用者不需要直接进入内部模块寻找每个算法的私有构造函数。

## 性能指标的解释边界

本报告中的性能提升是固定验收样例上的软件层成本比较，主要反映：

1. 开源接口复用已封装的矩阵组装和线路模板，减少重复 Python 逻辑。
2. 应用算法模板避免手写冗余门序，降低量子门数量或线路深度。
3. 统一结果结构减少后处理转换成本。

它不声称在真实量子硬件上已经获得物理运行加速。若后续进入硬件或含噪模拟评测，应额外报告 shots、噪声模型、保真度、成功概率和置信区间。当前 Perf-36 的结论限定为“开源原型软件层面的构建效率与样例成本提升”。

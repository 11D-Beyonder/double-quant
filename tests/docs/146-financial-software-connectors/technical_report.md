# 146 可视化分析工具能对接不少于6项常用金融软件技术报告

## 技术目标

本功能面向“可视化分析工具能对接不少于6项常用金融软件”的验收要求。金融分析平台在进入算法建模之前，通常需要先从外部金融软件或金融数据平台取得行情、指标、成分股、宏观数据等信息。如果只给出一个代码编辑入口，验收人员无法直接判断平台是否具备对接不同金融软件的能力。因此该功能被设计为金融编程开发页面的第一步，专门展示金融软件适配目录、连接方式、字段映射、样例数据和验证入口。

## 为什么这样实现

该能力的核心不是单个软件的静态说明，而是“多来源数据进入平台后的统一入口”。不同金融软件在连接方式、认证要素、字段命名和数据形态上差异明显：例如桌面终端、REST 网关、Python 数据服务、本地插件、数据目录和研究环境都属于常见接入方式。为了让验收过程可视化、可检查，界面没有把这些差异隐藏在后台配置中，而是把每个适配器的连接方式、认证要素、适配场景和字段转换关系直接展示出来。

这种实现方式有三个目的：第一，证明平台覆盖的软件数量超过6项；第二，证明每个软件不是简单列名，而是具有可解释的接入方式和字段标准化规则；第三，为后续数据格式处理和金融编程步骤提供统一的数据基础，避免把软件差异扩散到后续算法界面。

## 功能组成

该功能覆盖8项金融软件或金融数据平台：Wind、同花顺 iFinD、东方财富 Choice、Bloomberg、Refinitiv、Tushare Pro、JoinQuant、Qlib。每一项适配对象都包含以下信息：连接方式、认证要素、适配场景、源字段名称、标准字段名称、字段类型和样例行情数据。验收时可以通过左侧目录确认覆盖范围，通过右侧详情确认每个适配项的实际含义。

界面结构采用左侧目录和右侧详情的布局。左侧目录用于快速切换金融软件，避免页面变成长列表；右侧详情区用于展示当前软件的连接说明、字段映射和样例数据。顶部状态标签显示已覆盖的软件数量和标准字段数量，使验收人员可以直接确认“不少于6项”的数量要求。

## 字段标准化设计

不同金融软件对同一类行情字段的命名并不一致。例如证券代码可能叫 symbol、windCode、ticker 或 security；日期可能叫 tradeDate、date 或 datetime。为了让后续数据格式处理和金融编程不依赖具体软件，第一步把源字段统一映射为标准字段。标准字段包括证券代码、交易日期、开盘价、最高价、最低价、收盘价、成交量、成交额和复权因子。

标准字段映射的意义在于把外部软件差异转化为平台内部的一致数据契约。用户选择不同金融软件时，界面仍然展示同一组标准字段，说明这些外部数据可以进入相同的后续处理流程。这样做可以避免后续每个算法模板都为 Wind、iFinD、Choice 等软件分别写一套字段读取逻辑。

## 交互与状态流转

用户进入金融编程开发页面后，第一步默认显示金融软件对接面板。用户可以通过下拉选择器或左侧目录切换适配器。切换后，连接方式、认证要素、适配场景、字段映射表和样例数据表会同步更新。点击“验证适配器”时，页面会检查当前适配器的关键字段和样例数据是否完整，并给出校验状态；点击“生成标准数据格式”时，当前软件的样例数据被视为已经完成标准字段转换，可以进入第二步数据格式处理。

这种流程设计把“选择软件、查看规则、确认映射、交接数据”串成一个明确的 UI 闭环。验收截图中也对应标注了顶部导航、三步流程导航、当前步骤、软件目录、字段映射、样例预览和验证入口。

## 验收关注点

本功能的验收重点包括：是否展示不少于6项常用金融软件；是否每项软件都有连接方式说明；是否存在标准字段映射；是否提供样例数据预览；是否有适配器验证入口；是否能向后续数据格式步骤交接标准数据。截图中展示了8项适配对象，超过指标要求；字段映射和样例数据以表格形式呈现，能够支撑人工验收和后续扩展。

## 技术边界

本功能侧重“可视化对接能力和字段标准化能力”的展示与验证，不在验收材料中展开真实外部账号、终端会话或第三方数据授权细节。真实业务接入时，外部凭据和网络会话应由受控服务统一管理，前端只展示连接状态、字段契约和可验证的样例数据。这样既能满足验收对可视化对接能力的检查，又避免在交付材料中暴露敏感凭据。

## 技术结论

该实现把常用金融软件适配能力拆成独立的可视化步骤，通过8项适配目录、连接方式说明、标准字段映射、样例数据预览和验证入口，证明平台具备多金融软件接入和标准化处理能力。其设计重点是将外部软件差异收敛到统一字段模型，为后续数据格式治理和金融编程接口提供一致输入。
